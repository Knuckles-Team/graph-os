# GRAPHOS-DEPLOY-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-DEPLOY-R001` | **Worker topology manifest is digest-pinned.** GraphOS's Kubernetes worker-topology manifest pins its dispatch, ingest and other worker workloads, their horizontal pod autoscalers, and its stateful set to an exact image digest rather than a floating tag. | A manifest lint check fails any workload image reference in the manifest that is not digest-pinned. |
| `GRAPHOS-DEPLOY-R002` | **Executable release-qualification runbook.** GraphOS publishes an executable, step-by-step release-qualification runbook covering the graph engine, connector SDK, agent runtime, GraphOS itself, the web UI, and the connector package fleet, through production redeployment, as the companion procedure to the exit-criteria matrix. | Each runbook stage is backed by an automated check or script that a reviewer can run directly. |
| `GRAPHOS-DEPLOY-R003` | **Pre-push hooks always run the full gate suite.** GraphOS's pre-push git hook resolves to its actual pre-commit configuration file and runs its full gate suite before a push succeeds; a relocated configuration path or a missing hook installation is treated as a failure, never a silent pass-through. | A hook-audit test invokes the generated pre-push shim and confirms it executes the configured gates rather than exiting silently. |
| `GRAPHOS-DEPLOY-R004` | **mypy hook type-checks the test suite.** GraphOS's pre-commit mypy hook type-checks its test suite rather than excluding it, and the type errors that exclusion had hidden are fixed rather than suppressed. | The mypy hook runs against the test suite in continuous integration and passes with zero errors. |
| `GRAPHOS-DEPLOY-R005` | **Web UI rename cutover across GraphOS.** GraphOS's import sites, optional web UI package extra, package source reference, release workflow checkout step, preflight checks, and browser-control tests and docs all reference the renamed web UI package. | A focused test run and the offline lock check confirm every reference resolves against the renamed package. |
| `GRAPHOS-DEPLOY-R006` | **gateway-widgets extra pins a compatible connector floor.** GraphOS's `gateway-widgets` optional extra declares a minimum version for each fleet connector package equal to the first published release compatible with the agent runtime's current module layout, so installing the extra never pulls a connector package that imports a removed module. | The widget test suite passes when the extra is installed from the published package index. |
| `GRAPHOS-DEPLOY-R007` | **GraphOS hosts deployment doctor and skill certification.** GraphOS hosts the sole deployment doctor, skill-certification, OIDC-certification, skill-validation, and fleet-harness/skill-graph test modules, incorporating any behavior unique to the agent runtime's former deployment package, and its `pyproject.toml` is the canonical source of console-script registrations for this tooling so no equivalent script remains declared by the agent runtime. | A package-layout test confirms the agent runtime's deployment package is absent and every related console script resolves to a GraphOS-owned module. |
| `GRAPHOS-DEPLOY-R008` | **GraphOS hosts its own boundary modules.** GraphOS hosts its own security request-identity, error-surface, browser-auth and security-policy-middleware modules with their conformance tests; its own gateway and runtime health and metrics observability; its own profile-guard, install, release-channel, live-mount-guard, paths, workspace and config-admin core modules; its own hook-installer, agent-manager-dashboard, release-catalog and gateway-client modules; and its own connection-registry and engine-discovery modules under `graph_os.fleet`. | A package-layout census confirms these modules are imported only from their GraphOS location and the agent runtime no longer declares equivalents. |
| `GRAPHOS-DEPLOY-R009` | **GraphOS owns hosting/deployment configuration settings.** GraphOS owns the hosting and deployment configuration settings split out of the agent runtime's monolithic configuration module, while connector base settings move to the connector SDK's own configuration module and agent/model settings remain with the agent runtime. | A configuration-schema test confirms GraphOS resolves its hosting and deployment settings from its own module without importing the agent runtime's configuration internals. |
| `GRAPHOS-DEPLOY-R010` | **Ecosystem and repository development skills are published.** GraphOS publishes an ecosystem-wide development skill and its own repository development skill documenting architecture boundaries, build-host requirements, required gates, contract regeneration, and identity setup for working in this codebase; GraphOS's `AGENTS.md` is trimmed to navigation with a pointer to that skill. | A documentation-freshness check confirms the skill content matches current gate commands and `AGENTS.md` contains the pointer rather than duplicated procedure. |
| `GRAPHOS-DEPLOY-R011` | **Deployment layout test suite passes in full.** GraphOS's deployment manifest layout passes its full deployment test suite with no failing tests. | The deployment test suite reports all tests passing, including cases that previously failed on this layout. |
| `GRAPHOS-DEPLOY-R012` | **Pipelines dependency is referenced at main, never pinned.** GraphOS's pre-commit configuration and GitHub Actions workflows reference the shared pipelines repository at its default branch rather than a pinned commit, so GraphOS automatically tracks pipeline fixes. | A reference-pin lint check fails any pre-commit `rev:` or workflow `uses:` entry for the pipelines repository that names a commit instead of the default branch. |
| `GRAPHOS-DEPLOY-R013` | **Development and production deployment profiles.** GraphOS's deployment skills provide a development profile using Docker Compose on a single host with no or local identity, and a production profile using Kubernetes/Helm with external or local identity; each profile runs the graph engine as a sidecar, enforces an identity mode with a forced first administrator, applies default authorization policy, selects an appropriate secrets backend, and performs first-boot verification. These GraphOS-owned skills replace the agent runtime's retired deployment copies, and the connector SDK's federation capability replaces any direct graph-database mirror. | A first-boot test provisions each profile and confirms readiness, administrator creation, and the selected secrets backend before accepting traffic. |
| `GRAPHOS-DEPLOY-R014` | **Agent runtime split into connector SDK, GraphOS and engine.** The former agent runtime is split into separately published repositories: the connector SDK, GraphOS, and the graph engine, each publishing its own installable package so GraphOS depends on the others only through their public APIs. | GraphOS's dependency manifest pins each split repository's published package rather than a path into the former combined source tree. |
| `GRAPHOS-DEPLOY-R015` | **AVX2 guard test runs on any hosted runner.** GraphOS's AVX2 guard test validates CPU feature-detection logic without asserting that the execution host lacks the AVX2 instruction set, so it passes on both AVX2-capable and non-AVX2 hosts. | The guard test passes in continuous integration on a standard hosted runner in addition to a non-AVX2 target host. |
