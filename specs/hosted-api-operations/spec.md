# GRAPHOS-OPS — Hosted API and intent operations

## Status legend

`DRAFT` means requirements still need decisions; `READY FOR IMPLEMENTATION` means a contributor can implement the stated contract; `BUILDING` means a branch exists but has not met acceptance; `SOURCE LANDED` means code is on the default branch; `ACCEPTED` means the exact default-branch revision passed the contract, quality, and served-path tests in [test-spec.md](test-spec.md). A spec document being complete never changes delivery state. Evidence must name a commit, test command, result, and public CI or release URL. Individual capabilities can advance separately in the [coverage table](#capability-coverage); this document makes no blanket claim that earlier foundation code is accepted.

## Purpose and user stories

As an authenticated operator, I can discover every GraphOS capability through typed HTTP and six MCP intent verbs, invoke it under the same policy, and see a stable error or durable receipt. As an external contributor, I can add an operation in one registry and prove it is available on all allowed surfaces without hand-writing parallel authorization. As a fleet client, I can dynamically find and load native tools, prompts, resources, and skills without bypassing that authorization.

## Observable requirements

- **HO-01 Registry.** One immutable `OpSpec` registry defines stable dotted IDs, verb, typed parameters/results, binding, caller and executor scopes, principal rule, effect, confirmation, allowed surfaces, idempotency, stability, and audit class. A generated EG-bound op covers every wire-callable engine method except a reviewed exclusion naming its replacement or internal-only reason. Generated registry, descriptors, OpenAPI, clients, and digest are reproducible from pinned public package contracts.
- **HO-02 Invocation.** MCP, HTTP, A2A, and loaded fleet forwarders call one `invoke(op, params, verified_caller, surface, plan_ref?, idempotency_key?)` pipeline. It rejects unknown operations, forbidden surfaces, extra fields, caller-asserted identity/tenant, unverified identity, wrong principal kind, missing exact scopes, policy denial, or subject-read denial before effect. Caller-bound engine calls use verified caller claims. Service-executed operations require a caller domain scope, caller-side read check on the subject, allowlisted service scope, caller-owned durable records, and revocation rechecks for deferred effects.
- **HO-03 Effect and audit.** Exact read operations execute immediately. An exact write requires an idempotency key unless naturally idempotent. Natural-language selection never directly mutates. Destructive operations require a single-use ten-minute plan bound to operation, parameter digest, principal, tenant, policy revision, and registry digest. Human approval and identity administration initiated on MCP/A2A return a console step-up requiring the same human and fresh MFA. Governed write/admin effects reserve a durable tenant-scoped audit record *before* dispatch and link outcome/reconciliation after; an unavailable reservation refuses dispatch, and an uncertain post-effect write is marked indeterminate, never rolled back by claim. For GraphOS-source `INDETERMINATE` only, the shared error envelope may expose `error.details.audit_ref` as the opaque string `graphos_audit:<request_digest>:<reservation_seq>`, at most 99 characters. The digest is exactly 64 lowercase hexadecimal characters; the sequence is canonical decimal in the unsigned 64-bit range (0 through 18446744073709551615). The error projection accepts only the audit adapter's JSON-encoded two-element list `[request_digest, reservation_seq]`: require a string of at most 89 characters before JSON parsing, the exact digest shape, and an integer sequence (never a boolean) within that range. Invalid references are omitted; already-public handles, legacy handle formats, arbitrary strings and raw audit JSON are not public alternatives. The existing fixed `audit outcome unavailable` reason may be preserved independently of whether the reference is valid; no backend messages, private identity values or arbitrary detail fields are reflected. Other error codes and sources do not expose this field, and unknown-code refusal is unchanged. The handle identifies a reservation and grants no access: reconciliation independently authenticates the caller and checks tenant and reservation access. Boundary tests cover zero and maximum sequence, input bounds before parsing, malformed/type/hex/PII rejection and source/code isolation; a cross-consumer check exercises actual audit-adapter preflight and receipt validation with a synthetic valid provider receipt, which is not durable-provider qualification.
- **HO-04 MCP.** The resident tools are `find`, `ask`, `why`, `write`, `act`, `manage`, `find_tools`, `load_tools`, `unload_tools`, and `multiplexer_status`. A loaded native tool is visible only to that session and invokes `fleet.call` through HO-02 on every call. Discovery includes fleet tools, prompts, resources/templates, skills, and connector pack items; `find_tools(browse=true)` replaces `list_catalog`. `find` merges registry and fleet matches. Discovery, load, and call re-evaluate exact scopes and Eunomia policy. The default load cap is 64, hard maximum 256, idle expiry one hour; explicit LRU eviction is opt-in. Each load response includes native name, schema, and a `fleet.call` fallback; list-change notification is sent and queued for clients that do not refresh immediately.
- **HO-05 HTTP.** Each op has `POST /api/v1/ops/{op_id}` and may expose a generated resource route. The API publishes authenticated registry/OpenAPI discovery, cursor pagination, idempotency header, CSRF for cookie sessions, and a common success/error envelope. Native login, OAuth, SCIM, A2A, MCP, webhook, health and metrics routes are inventoried protocol routes. Retired hand-written domain routes are removed only with their consumers migrated.
- **HO-06 Error/version contract.** Every response carries `api_version=v1` and a SHA-256 registry digest. Engine errors preserve engine code and retryability from its packaged public error contract; fleet errors preserve child code and target. GraphOS errors use a closed enum including `UNAUTHENTICATED`, `UNKNOWN_OP`, `SURFACE_NOT_ALLOWED`, `PRINCIPAL_NOT_ALLOWED`, `SCOPE_REQUIRED`, `SUBJECT_ACCESS_DENIED`, `INVALID_ARGUMENT`, `CONFIRMATION_REQUIRED`, `STEP_UP_REQUIRED`, `PLAN_EXPIRED`, `PLAN_MISMATCH`, `PLAN_STALE`, `POLICY_DENIED`, `POLICY_UNAVAILABLE`, `LOAD_CAP_EXCEEDED`, `UNKNOWN_TOOL`, `UNAVAILABLE`, `TIMEOUT`, `RATE_LIMITED`, and `INTERNAL`. Messages and logs omit tokens and private identity/tenant values. Stable ops only add optional fields or open enum members within v1; breaking changes require a major version and migration note.
- **HO-07 Coverage.** GraphOS publishes domain ops for identity/admin, access/approval, capacity, finance/markets, query/search/ontology/analytics, federation, ingestion, decision/retrieval/policy, work/evolution, agents/browser, telemetry/security/usage/memory/graph, fleet, and infrastructure. Public `eg.*` bindings cover remaining wire-callable engine methods. Uncomposed dependencies return typed `UNAVAILABLE`; discovery does not advertise them as ready.
- **HO-08 Policy.** Eunomia narrows scope/principal authority at discover, load, and call. When enabled and unreachable it fails closed. When off, exact scopes still filter. Policy revision invalidates cache and loaded visibility; destructive/admin decisions are never cached. `mcp:discover`, `mcp:delegate`, and `mcp:admin` are exact scopes with no implied admin shortcut. Human clients never receive service-only infrastructure grants.
- **HO-09 Fresh checkout.** A public clone can run registry/contract tests with pinned package artifacts and local fixture identities, without a sibling checkout, private network, live identity provider, scanner daemon, or deployed environment. Served tests may provision an ephemeral local stack and are identified separately.
- **HO-10 Parity inventory.** Every former hosted intent/granular tool has one documented destination operation or an intentional drop reason. Public generated clients and compatibility notes identify a migration path for browser, terminal and agent callers; a legacy endpoint is removed only when its public successor is exercised through real serving composition.
- **HO-11 Atomic cutover.** The serving process boots exactly one FastMCP loop, one multiplexer and the ten resident names, with native forwarders registered only by the audited factory. It mounts the generated `/api/v1` sub-application and an explicit protocol-route table. Stale instructions, dead routes and unmounted usage routes are repaired or retired in the same change. Failed attachment of a resident tool is a boot failure, not a degraded claim of availability.

## Required operation families

Each family below uses the same typed registry, invocation steps and error envelope. A listed operation denotes a required public contract; implementation must bind to a released engine method or an existing GraphOS service before it is advertised as available. List/get paths are scoped to the caller's readable objects and cursor-paged. Every mutation declares exact idempotency and audit class.

The GraphOS contribution includes a machine-readable former-tool inventory: each old intent/granular name maps to one stable op ID or a documented drop with a reason. The agent owner can delete its old resolver and tool definitions only when this inventory, parity tests, and generated client are published. The server never imports that old implementation at runtime.

## Acceptance

1. Every public method and route is either an operation or an explicitly inventoried protocol route, and every supported operation has identical allow/deny semantics across allowed surfaces.
2. A denied, revoked, stale, or ambiguous mutation creates no effect; a successful governed effect has reservation and outcome evidence.
3. The generated contract, package, and fresh-checkout gates pass at the exact default-branch commit; an ephemeral served call proves MCP and HTTP reach the same handler and durable owner.
4. The scoped quality gates in [test-spec.md](test-spec.md) pass without suppressions, copied authority logic, or undisclosed private environment dependencies.

Requirement IDs are defined in [requirements.md](requirements.md); delivery state per ID is in `status.json`.
