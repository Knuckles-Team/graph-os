# GRAPHOS-OPS-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-OPS-R001` | **Native MCP/REST facade with A2A unary operations then streaming.** GraphOS provides a native MCP and REST host that fronts the engine and agent-utilities services, first exposing unary A2A operations (card, send, get, list, cancel) and then adding durable streaming on top of the same handlers. | Integration tests exercise the A2A unary endpoints against a fixture engine, followed by a separate test proving durable streaming delivery. |
| `GRAPHOS-OPS-R002` | **Scoped A2A task routing and fleet tool exposure.** GraphOS routes inbound A2A tasks to the correct operation handler and exposes, through its assembled multiplexer, only the caller-authorized subset of fleet tools, including typed work-item retrieval and listing bound by control leases and read classifications. | Integration tests assert inbound A2A tasks resolve to the correct handler and that multiplexer tool listings are filtered per caller. |
| `GRAPHOS-OPS-R003` | **Remove multiplexer skill/prompt harvest path.** GraphOS removes the multiplexer's legacy skill and prompt harvesting and static hydration code path, sourcing skills and prompts only through the fleet discovery surface. | A regression test confirms the retired harvest module is absent and unimportable at runtime. |
| `GRAPHOS-OPS-R004` | **FastMCP 4 bridge for the MCP server.** The GraphOS MCP bridge declares and runs on FastMCP 4 with native WebMCP support and a single consolidated event loop, matching the version already exercised by its own probes. | A semantic test suite plus a live probe confirm the deployed bridge reports FastMCP 4. |
| `GRAPHOS-OPS-R005` | **Stable auth error codes from the engine contract.** GraphOS consumes the engine's packaged error-code contract, including the stable AUTH_TENANT_MISMATCH, AUTH_AUDIENCE_MISMATCH, and AUTH_POLICY_VERSION_MISMATCH codes, and refuses to start when the installed engine package's contract is missing or inconsistent with its own generated bindings. | A contract test fails closed when the packaged engine error contract is absent or mismatched against the generated bindings. |
| `GRAPHOS-OPS-R006` | **Consume the engine's packaged wire-callable contract.** GraphOS reads the engine's packaged contract files for methods, errors, scopes, and JSON schemas from the installed package, and binds an operation only for engine methods whose contract marks them wire-callable. | A package-contract test confirms the generated registry excludes any method not marked wire-callable in the installed engine contract. |
| `GRAPHOS-OPS-R007` | **Immutable operation registry with digest and authorization.** GraphOS defines one immutable OpSpec registry with typed enums for verb, surface, effect, and scope, producing a canonical form and a stable SHA-256 registry digest, and evaluates per-call authorization at find time. | Unit tests in tests/api/test_registry.py cover canonical-form stability, digest reproducibility, and authorized-evaluation outcomes. |
| `GRAPHOS-OPS-R008` | **Generated engine-bound operations with exclusions.** GraphOS generates one registry operation per wire-callable engine method through its engine-binding generator, skipping only methods listed in its exclusions file with a recorded replacement or internal-only reason. | Unit tests in tests/api/test_eg_binding.py assert full wire-callable method coverage minus the documented exclusions. |
| `GRAPHOS-OPS-R009` | **Single invoke pipeline for authority, effect, and audit.** GraphOS funnels every MCP, HTTP, A2A, and fleet call through one invoke pipeline that enforces surface, principal rule, exact scopes, policy, and subject-read checks in order, executes service-bound operations through a dedicated executor, gates destructive effects behind a single-use plan reference bound to the operation and policy revision, and requires console step-up with fresh authentication before admin or human-approval effects complete. | Integration tests exercise allow, deny, plan-expiry, and step-up paths through the invoke pipeline. |
| `GRAPHOS-OPS-R010` | **Closed error enum and one response envelope.** GraphOS defines a closed error-code enum, including UNAUTHENTICATED, UNKNOWN_OP, SCOPE_REQUIRED, and POLICY_DENIED, together with a generated engine-error mapping, and converts every surface's response through one shared to_envelope function. | Unit tests check envelope shape and error-code mapping, and a generator diff check compares output against the packaged engine contract. |
| `GRAPHOS-OPS-R011` | **Six resident MCP verbs with typed discovery.** GraphOS implements the six resident MCP verbs (find, ask, why, write, act, manage) through a shared verb constructor with typed input schemas, exposes registry entries as graphos:// resources, and includes the registry digest in the server's published instructions. | Unit tests in tests/api/test_mcp_verbs.py cover verb schema validation, resource listing, and digest presence. |
| `GRAPHOS-OPS-R012` | **Bounded resolver for natural-language operation lookup.** GraphOS resolves natural-language and partial queries to registry operations using combined lexical and semantic ranking over generated descriptors, a tenant- and policy-partitioned outcome moving average, and a bounded result cache, falling any unmatched ask call back to a read-only natural-language query preview rather than a direct mutation. | Unit tests in tests/api/test_resolve.py cover ranking order, cache bounds, and the preview-only fallback behavior. |
| `GRAPHOS-OPS-R013` | **Generated HTTP API for every registry operation.** GraphOS exposes each registry operation at POST /api/v1/ops/{op_id} plus generated resource routes on a dedicated sub-application, with an authentication dependency, CSRF protection for cookie sessions, cursor pagination, idempotency-key handling, and discovery endpoints for the registry and OpenAPI document. | Integration tests in tests/api/test_http_*.py cover routing, authentication, CSRF enforcement, and pagination and idempotency behavior. |
| `GRAPHOS-OPS-R014` | **Identity self-service and admin operations.** GraphOS exposes identity operations covering self-service, admin management of users, sessions, API keys, service accounts, roles, and groups, identity-provider configuration with dry-run, policy and mode transitions, issuer rotation, audit export and verification, and SCIM client management, requiring identity:admin scope and fresh console step-up for mutations. | Integration tests exercise each identity operation and confirm scope and step-up enforcement on admin mutations. |
| `GRAPHOS-OPS-R015` | **Access elevation, approval, and lease operations.** GraphOS exposes access operations for elevation requests, approval and denial, lease listing, authorization checks, and policy explanation through a consolidated access service that enforces identical outcomes and a no-self-approval rule across every surface. | Integration tests confirm consistent allow/deny outcomes across surfaces and reject a self-approval attempt. |
| `GRAPHOS-OPS-R016` | **Capacity status and throttle mode operations.** GraphOS exposes capacity status, cell update, and throttle status/mode operations backed by a read/config facade over the capacity controller, restricting throttle mode changes to the bounded observe/enforce enum under admin scope. | Integration tests confirm capacity reads match the underlying capacity cell and that a denied update leaves throttle state unchanged. |
| `GRAPHOS-OPS-R017` | **Finance and markets operations with tenant isolation.** GraphOS exposes finance and markets operations, executing market reads server-side through the service executor under the finance:read scope, and gating position and paper-trading actions behind caller and subject ownership checks so no caller can see another tenant's account data. Delivered as the rollup of `GRAPHOS-OPS-R017.1` through `GRAPHOS-OPS-R017.2`. | Integration tests, including a negative cross-tenant case, confirm market reads and paper/position actions respect per-caller account binding. |
| `GRAPHOS-OPS-R017.1` | **Tenant-scoped market reads under finance:read.** GraphOS executes market reads server-side through the service executor under the finance:read scope, refusing with zero provider calls on a missing or mismatched tenant/account binding. | Tests confirm a matching binding reaches the provider and a missing or cross-tenant binding refuses before any provider call. |
| `GRAPHOS-OPS-R017.2` | **Position and paper-trading actions with subject ownership checks.** GraphOS gates position and paper-trading actions behind caller and subject ownership checks sourced from the engine's subject-ownership contract, so no caller can act on another tenant's account. Blocked on the epistemic-graph v2.28 subject-ownership contract (not yet pinnable; current pin is `epistemic-graph>=2.27.0,<3.0.0`). | An integration test, including a negative cross-tenant case, confirms paper/position actions respect per-caller subject ownership once the v2.28 contract is pinned. |
| `GRAPHOS-OPS-R018` | **Query, search, ontology, and analytics operations.** GraphOS exposes query (uql, sparql, sql, sql_schema), search, indexes, ontology, and analytics.series operations that execute caller-bound engine queries without a separate local ontology store or SQL string interpolation. Delivered as the rollup of `GRAPHOS-OPS-R018.1` through `GRAPHOS-OPS-R018.2`. | Integration tests confirm each query/search/ontology/analytics operation reaches the engine and honors tenant and budget limits. |
| `GRAPHOS-OPS-R018.1` | **Sparql, sql_schema, and ontology operations.** GraphOS exposes sparql and sql_schema query routes and the ontology operation surface (value types, property types, interfaces, schema graph/summary, lint, generate, validate, load, export, catalogue) against the engine, without a separate local ontology store or SQL string interpolation. | Tests confirm the sparql and sql_schema routes and the ontology operation surface reach the engine. |
| `GRAPHOS-OPS-R018.2` | **Uql, sql, search, indexes, and analytics.series operations.** GraphOS exposes uql and sql query operations, search, indexes, and analytics.series operations that execute caller-bound engine queries and honor tenant and budget limits. | Integration tests confirm each operation reaches the engine and honors tenant and budget limits. |
| `GRAPHOS-OPS-R019` | **Federation source registration and sharing operations.** GraphOS exposes federation.sources operations for register, list, get, share, unshare, and probe, treating registration and sharing as governed writes and redacting credentials from probe results. Delivered as the rollup of `GRAPHOS-OPS-R019.1` through `GRAPHOS-OPS-R019.2`. | Integration tests confirm a shared source is visible only to its owner and grantees and that revocation blocks a subsequent probe. |
| `GRAPHOS-OPS-R019.1` | **Federation source register, list, get, and probe.** GraphOS exposes federation.sources register, list, get, and probe, treating registration as a governed write and redacting credentials from probe results. | Integration tests confirm registration is a governed write and that probe results redact credentials. |
| `GRAPHOS-OPS-R019.2` | **Federation source share and unshare.** GraphOS exposes federation.sources share and unshare as governed writes, so a shared source is visible only to its owner and grantees and revocation blocks a subsequent probe. | Integration tests confirm a shared source is visible only to its owner and grantees and that revocation blocks a subsequent probe. |
| `GRAPHOS-OPS-R020` | **Ingest operations through a typed SDK runner facade.** GraphOS exposes ingest operations for repository indexing, source sync, pack and job management, drift listing and repair with approval, and embedding admission and re-embedding, calling the ingestion SDK only through a typed runner facade and returning a typed UNAVAILABLE error when that runner is not composed. Delivered as the rollup of `GRAPHOS-OPS-R020.1` through `GRAPHOS-OPS-R020.5`. | Integration tests confirm sync returns a durable job receipt and that an absent runner fails closed with UNAVAILABLE. |
| `GRAPHOS-OPS-R020.1` | **Typed ingest runner port and the source-sync entry point.** GraphOS defines the one typed port it calls the ingestion SDK through and exposes `ingest.sources.sync`, failing closed with `UNAVAILABLE` when no runner is composed. | A test proves a durable job receipt on success and a typed `UNAVAILABLE` refusal when the runner is absent. |
| `GRAPHOS-OPS-R020.2` | **Repository indexing and source inventory operations.** GraphOS exposes `ingest.repositories.index` and `ingest.sources.{list,status}` through the same typed runner port. | Integration tests confirm each operation reaches the runner and fails closed with `UNAVAILABLE` when the runner is absent. |
| `GRAPHOS-OPS-R020.3` | **Pack and job management operations.** GraphOS exposes `ingest.packs.*` and `ingest.jobs.*` through the same typed runner port. | Integration tests confirm pack and job operations reach the runner and report durable job state. |
| `GRAPHOS-OPS-R020.4` | **Drift listing and repair-with-approval operations.** GraphOS exposes `ingest.drift.{list,get,repair_propose,repair_approve}`, gating repair behind an approval reference. | Integration tests confirm drift repair previews and audits its effect before applying it. |
| `GRAPHOS-OPS-R020.5` | **Embedding admission and re-embedding operations.** GraphOS exposes `ingest.embedding.{admit,reembed}` through the same typed runner port. | Integration tests confirm embedding operations reach the runner and report durable job state. |
| `GRAPHOS-OPS-R021` | **Decision, retrieval, and policy operations.** GraphOS exposes decide, retrieval, context, freshness, policy, and swarm read operations while restricting decision-commit actions to the service executor, so no caller can materialize an agent decision using only a human-scoped token. | Integration tests confirm decision commits are service-only and that provenance is attached to each result. |
| `GRAPHOS-OPS-R021.1` | **Decide operations (service-executed) — decide slice.** Implements the decide portion of `GRAPHOS-OPS-R021`: `decide.*` operations that evaluate and commit agent decisions, routing the commit path through the service executor only (never the caller-bound path) and attaching provenance to each result. | A test confirms a human-scoped caller cannot invoke the commit path directly and that every decide result carries provenance. |
| `GRAPHOS-OPS-R021.2` | **Retrieval, context, and freshness read operations — retrieval slice.** Implements the retrieval portion of `GRAPHOS-OPS-R021`: `retrieval.*` read operations, including context-budgeted retrieval and freshness checks, executing caller-bound engine queries without a local cache substitute. | A test confirms a retrieval call reaches the engine under the caller's own authority and respects a context budget. |
| `GRAPHOS-OPS-R021.3` | **Policy and swarm read operations — policy slice.** Implements the policy portion of `GRAPHOS-OPS-R021`: `policy.*` and `swarm.*` read operations surfacing the active policy state and swarm topology to an authorized caller. | A test confirms policy and swarm reads are caller-scoped and read-only. |
| `GRAPHOS-OPS-R022` | **Work and evolution loop operations.** GraphOS exposes work-item and offer operations plus evolution loop, schedule, and proposal operations, with its daemon acting only as a status/run/pause facade while durable loop state remains owned by the underlying service. | Integration tests confirm run/pause requires the loops:control scope, reads require loops:read, and a repeated run stays idempotent. |
| `GRAPHOS-OPS-R022.1` | **Work-item and offer operations — work slice.** Implements the work portion of `GRAPHOS-OPS-R022`: `work.*` operations for work-item and offer read/write access, bound by the same control leases the fleet-facing listing already enforces. | A test confirms a work-item write requires the declared scope and that offers are visible only to their bound principal. |
| `GRAPHOS-OPS-R022.2` | **Evolution loop, schedule, and proposal operations — evolution slice.** Implements the evolution portion of `GRAPHOS-OPS-R022`: `evolution.*` operations for loop status/run/pause, schedule, and proposal access, with the daemon acting only as a facade while durable loop state remains owned by the underlying service. | A test confirms run/pause requires the `loops:control` scope, reads require `loops:read`, and a repeated run stays idempotent. |
| `GRAPHOS-OPS-R023` | **Agent, browser, RLM, and fleet call operations.** GraphOS exposes agent, A2A task, RLM, browser, and fleet operations, including fleet.call, deriving each loaded tool's effect classification from its annotation so every call still passes through the invoke pipeline rather than bypassing it. | Integration tests confirm every loaded fleet tool call reaches the invoke pipeline and no direct child dispatch bypasses it. |
| `GRAPHOS-OPS-R024` | **Telemetry, security, usage, and admin operations.** GraphOS exposes telemetry, security, operational (doctor, config, backup, restore, tenants), usage, memory, and graph operations, sourcing usage data from the engine and requiring destructive backup, restore, and tenant actions to pass console step-up with a durable audit record. | Integration tests confirm backup, restore, and tenant actions cannot complete from a plain confirmation and require step-up plus audit. |
| `GRAPHOS-OPS-R024.1` | **Telemetry operations — telemetry slice.** Implements the telemetry portion of `GRAPHOS-OPS-R024`: `telemetry.*` operations bound to the engine's tenant-scoped telemetry method. | A test confirms a telemetry read is tenant-scoped and reaches the engine. |
| `GRAPHOS-OPS-R024.2` | **Security operations — security slice.** Implements the security portion of `GRAPHOS-OPS-R024`: `security.*` operations surfacing the current security posture to an authorized caller. | A test confirms a security read requires its declared scope. |
| `GRAPHOS-OPS-R024.3` | **Usage operations — usage slice.** Implements the usage portion of `GRAPHOS-OPS-R024`: `usage.*` operations sourcing usage data from the engine rather than a local counter. | A test confirms a usage read reaches the engine and reflects tenant-scoped data. |
| `GRAPHOS-OPS-R024.4` | **Memory operations — memory slice.** Implements the memory portion of `GRAPHOS-OPS-R024`: `memory.*` operations over the agent memory store, bound by the caller's own authority. | A test confirms a memory read/write is scoped to the caller's own tenant. |
| `GRAPHOS-OPS-R024.5` | **Operational admin operations — admin slice.** Implements the operational-admin (doctor, config, backup, restore, tenants) portion of `GRAPHOS-OPS-R024`: `ops.*` operations requiring destructive backup, restore, and tenant actions to pass console step-up with a durable audit record. Graph, query, search, and ontology administration are out of scope for this slice; GraphOS's host-composition cutover lane owns them as `GRAPHOS-HOST-R026.x`. | A test confirms backup, restore, and tenant actions cannot complete from a plain confirmation and require step-up plus audit. |
| `GRAPHOS-OPS-R025` | **Generated registry, OpenAPI, and client artifacts.** GraphOS's generator script regenerates the operation registry, descriptors, OpenAPI document, engine-error module, and Python and TypeScript clients from the packaged engine contract, producing reproducible output under its generated-artifact directories. | A generator diff/drift test confirms regenerated artifacts match the committed output for a pinned engine contract. |
| `GRAPHOS-OPS-R026` | **API surface and compatibility drift gates.** GraphOS enforces its API-surface and backward-compatibility drift gates as pre-commit hooks, each backed by a dedicated test. | Unit tests for each drift gate confirm it fails when a corresponding drift is introduced, and the pre-commit hook runs them on every commit. |
| `GRAPHOS-OPS-R026.1` | **API-surface drift gate — api-surface slice.** Implements the api-surface portion of `GRAPHOS-OPS-R026`: a pre-commit hook that fails when the generated registry's public surface (operation IDs, HTTP routes, and MCP verb set) changes without a corresponding reviewed baseline update. | A dedicated unit test confirms the gate fails when an operation is added, removed, or has its public shape changed without updating the checked baseline. |
| `GRAPHOS-OPS-R026.2` | **Backward-compatibility drift gate — backward-compat slice.** Implements the backward-compat portion of `GRAPHOS-OPS-R026`: a pre-commit hook that fails when a previously published operation is removed or has a required field narrowed in an incompatible way. | A dedicated unit test confirms the gate fails when a previously published operation's compatible shape is broken. |
| `GRAPHOS-OPS-R027` | **Authority-parity test across principals and surfaces.** GraphOS maintains an authority matrix fixture covering every principal kind, operation, and surface combination, and a parity test asserting the generated registry enforces identical allow/deny outcomes against it. | The authority-parity test suite runs against the authority matrix fixture and passes with no mismatches. |
| `GRAPHOS-OPS-R028` | **Exported domain scope classes.** GraphOS defines and exports its domain scope classes, including finance:read, fleet:read, fleet:control, loops:read, loops:control, ops:read, and ops:admin, for consumption by the engine's scope registry. | Unit tests confirm each exported scope triple matches its declared class and is consumed without duplication. |
| `GRAPHOS-OPS-R029` | **Single resident-tool server cutover.** GraphOS's server factory registers only the six resident MCP verbs plus find_tools, load_tools, unload_tools, and multiplexer_status, mounts the generated /api/v1 sub-application and an explicit protocol-route table, and removes the retired granular tool registrars, hand-written action-tool routes, and legacy fleet routes in the same change. | A boot/integration test confirms the running server exposes exactly the resident tool set and mounted routes with the retired modules absent. |
| `GRAPHOS-OPS-R030` | **Accurate MCP server and API documentation.** GraphOS keeps its MCP server, API, and status documentation accurate to the live six-verb MCP surface and generated HTTP API, replacing any outdated tool-count or endpoint description. | A documentation-accuracy check confirms the documented verb and tool counts match the live registry. |
| `GRAPHOS-OPS-R031` | **Published tool-to-operation parity inventory.** GraphOS publishes a complete parity inventory mapping every former hosted intent verb and tool to its destination operation or a documented intentional drop, so that a consuming agent project can remove its legacy intent-tool definitions only once that inventory and its generated client are published. | A parity-inventory test confirms full coverage of former tool names against the published mapping. |
| `GRAPHOS-OPS-R031.1` | **Fleet meta-tool parity mapping — resident fleet slice.** Implements the resident-fleet-tool slice of `GRAPHOS-OPS-R031`: GraphOS publishes, in docs, the parity mapping from each of its four resident fleet meta-tools (`find_tools`, `load_tools`, `unload_tools`, `multiplexer_status`) to its destination operation. | A parity-inventory test confirms the published mapping's keys and values match the live `FLEET_OPERATIONS` registry exactly. |
| `GRAPHOS-OPS-R032` | **Identity dependency inversion via ports.** GraphOS's webui_host, webui_co_service, and mcp_server modules depend only on the Protocol and DTO definitions in graph_os.identity.ports, with the concrete identity runtime constructed once in the serving composition root and injected into each. | A static dependency-graph check confirms each module imports only graph_os.identity.ports and not the concrete identity implementation. |
| `GRAPHOS-OPS-R033` | **Dynamic multiplexer discovery, load, and call.** GraphOS implements find_tools (with browse=true replacing the former catalog listing), load_tools, unload_tools, and multiplexer_status over one per-caller-filtered catalog spanning fleet tools, prompts, resources, skills, and connector items, enforcing a default load cap of 64 (hard maximum 256), one-hour idle expiry, opt-in LRU eviction, and routing every loaded tool's body through a fleet call with the caller's delegated credential. | Integration tests confirm the load cap, idle expiry, and that each loaded tool call is dispatched through the fleet-call path rather than directly. |
| `GRAPHOS-OPS-R034` | **Eunomia narrowing-only policy enforcement.** GraphOS applies its policy engine as a narrowing-only step at discovery, load, and every call, always leaving exact-scope filtering in place when policy is off, failing closed when policy is enabled but unreachable, defaulting to on for local and external deployments and off only for the none deployment mode, with its doctor check warning when policy is disabled. | Integration tests cover the off, on, and unreachable policy states, and a doctor-check test confirms the warning fires when policy is off. |
| `GRAPHOS-OPS-R035` | **Multiplexer registration reduced to four resident tools.** GraphOS replaces its multiplexer's meta-tool registration with the four resident tools (find_tools, load_tools, unload_tools, multiplexer_status), and narrows its session-visibility middleware to routing list and call requests only, no longer making authorization decisions itself. | An integration test confirms the middleware denies nothing on its own and that authorization is enforced solely by the invoke pipeline. |
| `GRAPHOS-OPS-R036` | **Pre-dispatch audit reservation for governed effects.** Before any governed write or admin effect, GraphOS reserves a tenant-scoped, idempotent pending audit record through the engine's audit-append operation using verified service claims, links the eventual outcome back to that reservation, and refuses dispatch when the operation has no declared audit class or the durable audit writer is unavailable. | Integration tests confirm a missing audit class or unreachable audit writer blocks dispatch and that a completed effect links to its reservation. |
| `GRAPHOS-OPS-R037` | **Native first-party A2A facade.** GraphOS exposes a first-party, natively hosted A2A facade rather than proxying through an external bridge, serving card, send, get, list, and cancel operations directly from its own server process. | Integration tests exercise the native A2A endpoints without any external bridge dependency. |
| `GRAPHOS-OPS-R038` | **Generated OpenAPI served through Swagger UI.** GraphOS generates an OpenAPI document from its operation registry and serves it through a browsable Swagger UI page. | An integration test confirms the served OpenAPI document matches the generated registry and renders through the Swagger UI endpoint. |
