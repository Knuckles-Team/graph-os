# GRAPHOS-IDENTITY-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-IDENTITY-R001` | **Elevation request, approve, and revoke surfaces.** GraphOS exposes elevation request, approval, and revoke actions through its web console, its A2A authority boundary, and chat-based tooling, with each surface invoking the engine's access service rather than deciding locally. | Verified by an integration test exercising the REST and MCP access operations from each surface and confirming self-approval and delegated-approval attempts are denied. |
| `GRAPHOS-IDENTITY-R002` | **Domain scopes consume the generated scope registry.** GraphOS's own domain scopes use the shared scope classes (user, domain, service-only, approver, admin) and are kept consistent with the single generated scope registry rather than a separately maintained list. | Verified by a registry property test asserting every scope GraphOS advertises matches the generated registry's name and class. |
| `GRAPHOS-IDENTITY-R003` | **Persistent local token issuer with secret-backed key.** GraphOS runs a persistent local token issuer that publishes discovery and JWKS metadata under a well-known path, stores its signing key as a secret reference, rotates keys with bounded overlap, and exchanges tokens from an external identity provider or a local authenticator for a verified local principal token. | Verified by a contract test validating discovery/JWKS responses, stable token subject identity, and bounded-overlap key rotation. |
| `GRAPHOS-IDENTITY-R004` | **Loopback bootstrap principal with origin guarding.** In unauthenticated mode, GraphOS resolves a request as the bootstrap principal through the ordinary RBAC and scope path, refuses non-loopback binds unless an explicit exposure acknowledgment is supplied, validates the Host header and same-origin Origin on cookie-mutating requests, and shows an unsecured-mode banner, page title, and doctor diagnostic, with the previously identified authentication bypasses removed. | Verified by a served HTTP/MCP test asserting loopback-only access, Host/Origin rejection before token issuance, and the unsecured-mode indicators across session, status, and initialize responses. |
| `GRAPHOS-IDENTITY-R005` | **Local account lifecycle with server-side sessions.** GraphOS implements local login, logout, registration, password change, and password reset backed by opaque server-side sessions, a CSRF token for cookie-based authentication, session-fixation rotation on login and privilege change, and uniform public error responses that never reveal whether an account exists. | Verified by an end-to-end account-lifecycle test covering CSRF validation, session rotation, and uniform throttled responses for unknown users and wrong passwords. |
| `GRAPHOS-IDENTITY-R006` | **Optional MFA with TOTP, WebAuthn, and recovery codes.** GraphOS supports TOTP, WebAuthn, and one-use recovery codes for multi-factor authentication, with enrollment optional by default globally while an administrator can require it for members of a configured group. | Verified by MFA ceremony tests covering valid and replayed TOTP codes, WebAuthn origin and signature-counter checks, single-use recovery codes, and enforced enrollment for a required group. |
| `GRAPHOS-IDENTITY-R007` | **Admin console tabs with mapping dry-run and mode wizard.** GraphOS's web console provides identity administration tabs for users, sessions, providers, and policy, a dry-run view that previews the roles an identity-provider mapping rule would assign, and a guided wizard for switching authentication mode. | Verified by a browser-driven test exercising each admin tab, the mapping dry-run preview, and a full mode-transition walkthrough. |
| `GRAPHOS-IDENTITY-R008` | **API keys and service accounts replace static MCP tokens.** GraphOS issues expiring API keys and service accounts in place of static MCP tokens, intersects a key's effective scopes with its current owner's scopes on every use, rejects approver-class scopes on keys, and denies a revoked or expired key immediately, with no static-token compatibility path. | Verified by an API-key contract test asserting scope intersection at use time and immediate denial of a revoked, expired, or approver-scoped key. |
| `GRAPHOS-IDENTITY-R009` | **Multi-provider OIDC with mapping rules and JIT policy.** GraphOS authenticates through multiple OIDC providers using PKCE, state, and nonce verification, applies deterministic ordered mapping rules with configurable just-in-time user creation or denial, supports a preset configuration for a common identity provider, migrates existing identity links idempotently, and sends a logout hint to the provider where supported. | Verified by an OIDC integration test against mock issuers asserting PKCE/nonce/state validation, mapping-rule outcomes, idempotent link migration, and hinted logout. |
| `GRAPHOS-IDENTITY-R010` | **LDAPS bind with nested group sync.** GraphOS binds to a directory over LDAPS, escapes search filters, and synchronizes group membership including nested Active Directory groups, deprovisioning access for disabled directory accounts. | Verified by an integration test against a mock TLS LDAP directory covering escaped filters, bounded nested-group resolution, and deprovisioning of a disabled account. |
| `GRAPHOS-IDENTITY-R011` | **SCIM 2.0 provisioning server.** GraphOS exposes a SCIM 2.0 server bound to a provider-specific service credential, supporting user and group provisioning and deprovisioning without deleting owned data. | Verified by a SCIM contract test covering create/update/patch/deactivate flows and rejection of a token scoped to a different provider. |
| `GRAPHOS-IDENTITY-R012` | **SAML sign-in brokered through an OIDC provider.** GraphOS supports SAML identity providers by brokering authentication through an existing OIDC provider rather than implementing a native SAML service-provider stack, since native SAML assertion processing is deferred. | Verified by an integration test asserting a brokered SAML sign-in yields a verified OIDC-backed identity while a raw, unbrokered SAML assertion is rejected. |
| `GRAPHOS-IDENTITY-R013` | **Identity CLI commands and doctor diagnostics.** The GraphOS identity CLI supports claim, link-claim, transition, reset-admin, and rotate commands with profile-aware defaults, and its doctor diagnostic reports a failing check for an exposed unauthenticated mode or an automatically generated secret. | Verified by a CLI contract test asserting each command's typed result and a doctor test asserting failing diagnostics for an exposed mode and an auto-generated secret. |
| `GRAPHOS-IDENTITY-R014` | **Shared RBAC decision oracle across identity modes.** GraphOS runs the same principal-by-scope-by-action-by-resource decision table against its unauthenticated, local, and external authentication modes, the last using mock OIDC and LDAP providers, and asserts identical allow/deny outcomes, reason codes, and claims digest for each principal across modes, including after a full mode-transition round trip. | Verified by a cross-mode oracle test comparing decision-table results and claims digests across all three modes. |
| `GRAPHOS-IDENTITY-R015` | **Identity operations documentation and cutover runbook.** GraphOS documents its identity and access operations and configuration, and provides a runbook for cutting an existing deployment over between authentication modes, referencing a committed browser sign-in probe as the verification step for an external provider. | Verified by following the documented runbook end to end against a test deployment and confirming each described step and diagnostic matches observed behavior. |
| `GRAPHOS-IDENTITY-R016` | **Optional SMTP adapter for identity email.** GraphOS optionally sends password-reset, verification, and invitation email through a configurable SMTP adapter; when no adapter is configured, email-only affordances are hidden while administrator reset and recovery-code paths remain available. | Verified by a notification test asserting a one-use reset email is sent when SMTP is configured and that email-only UI options are hidden when it is absent. |
| `GRAPHOS-IDENTITY-R017` | **Remove the unauthenticated opt-out once clients migrate.** Once every GraphOS client path, including bootstrap, REST, MCP, A2A, CLI, and background service calls, carries a verified local-issuer or permitted service token, GraphOS stops relying on the engine's unauthenticated opt-out so the engine refuses any unsigned request. | Verified by a served test asserting every client entry point is denied when its token is missing, expired, or has the wrong audience, with no unsigned retry or fallback path exercised. |
| `GRAPHOS-IDENTITY-R018` | **Identity administration operations for self, admin, config.** GraphOS exposes identity operations covering the authenticated caller's own record, administrator management of users, sessions, API keys, service accounts, roles, groups, identity providers with mapping dry-run, policy, mode, issuer, audit, and SCIM client configuration, all requiring exact identity-admin scope, console origin, and fresh multi-factor authentication for mutations. | Verified by an integration test exercising each identity operation and asserting admin mutations are denied without exact scope, console origin, or fresh MFA. |
| `GRAPHOS-IDENTITY-R019` | **Access operations for elevation and approval decisions.** GraphOS exposes access operations for elevation request, list, revoke, and approve/deny, approval listing and grant/deny, lease management, access checks, and policy explanation, all backed by the engine's access authority with no separate GraphOS-local approval or lease record. | Verified by an access-operations contract test asserting self-approval and delegated-approval attempts are denied and that REST and MCP surfaces return identical decisions. |
| `GRAPHOS-IDENTITY-R020` | **Domain scope registry covers finance, fleet, loops, ops.** GraphOS registers and exports its domain scopes, including finance read, fleet read and control, loops read and control, and ops read and admin, each with an exact name and scope class, consuming the generated engine scope registry rather than a separate list. | Verified by a registry property test asserting each exported scope's name and class matches the generated registry. |
| `GRAPHOS-IDENTITY-R021` | **Identity wiring depends only on identity ports.** GraphOS's web host, web co-service, and MCP server packages depend only on the identity ports protocols and DTOs for identity behavior, with the concrete issuer, session, and authority implementations constructed once in the serving composition root and injected, removing the prior direct dependencies between these packages. | Verified by an import-graph and composition test asserting a single constructed implementation per port, no import cycle, and compliance with the configured dependency-count threshold. |
| `GRAPHOS-IDENTITY-R022` | **Fleet authorization fails closed on exact scopes.** GraphOS's fleet capability check accepts only the exact fleet scope for a requested operation rather than treating a general admin or cluster-admin scope as sufficient, applies the same check to local stdio transport as to any other transport, denies dispatch of an unrecognized native tool rather than allowing it by default, and enforces this filtering on every served MCP request regardless of which code path constructed the server. | Verified by positive and negative tests asserting an admin-only or cluster-admin-only caller is denied fleet access, an unknown tool is denied, and stdio-transport requests are checked identically to networked requests. |
| `GRAPHOS-IDENTITY-R023` | **Native, self-refreshing credentials for MCP clients.** GraphOS issues and refreshes its own service-account or API-key tokens in process and serves them directly to IDE and agent MCP clients, removing the need for an external scheduled credential-refresh process or a file-based token cache read by a separate bridge process. | Verified by a client integration test asserting an MCP client obtains and automatically renews a working token from GraphOS with no external refresh process or cached credential file. |
| `GRAPHOS-IDENTITY-R024` | **Committed browser and Keycloak SSO probe.** GraphOS provides a committed, reusable script that drives a real browser through sign-in against an external OIDC provider such as Keycloak and verifies the resulting session, replacing any uncommitted ad hoc probe. | Verified by running the committed probe against a test identity-provider realm and confirming it reports a successful authenticated session. |
