# GRAPHOS-A2A-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-A2A-R001` | **A2A facade over the engine and agent services.** graph-os implements A2A as a facade over the public graph-engine and agent-utilities services exposed through MCP and REST, starting with unary agent-card discovery and task send/get/list/cancel, then adding durable task streaming and resubscribe without a second task store. | Proven by contract tests covering the unary task operations and a durable stream/resubscribe fixture. |
| `GRAPHOS-A2A-R002` | **Inbound task routing with caller-filtered tool exposure.** graph-os routes an inbound A2A task through the existing agent orchestration port into an engine-backed work item, and selects the agent and its exposed tool subset through caller-filtered assembly so a caller sees only the tools its authorization permits. | Proven by integration tests asserting routed tasks map to durable work-item identities and exposed tool subsets match the caller's authorization. |
| `GRAPHOS-A2A-R003` | **No duplicate skill or prompt harvesting in the multiplexer.** graph-os removes the multiplexer's separate skill and prompt harvesting path so there is exactly one owner for tool, skill, and prompt discovery, with no duplicate ingestion path remaining in the running package. | Proven by a runtime absence check confirming no duplicate harvest path is present or reachable in the deployed package. |
| `GRAPHOS-A2A-R004` | **Served MCP bridge runs FastMCP 4, matching its declared version.** graph-os's deployed MCP bridge runs on FastMCP 4 end to end, including native WebMCP and a single composition loop, so the dependency version it declares matches the version actually serving requests. | Proven by semantic tests run against the exact declared FastMCP and engine dependency versions, and a live-deployment probe confirming the served version. |
| `GRAPHOS-A2A-R005` | **Durable, fail-closed A2A approval exchange for tool calls.** graph-os defines a human approval exchange for a pending tool-call effect in the A2A contract: the task enters an input-required state and a signed approval message bound to that specific pending call is required before the effect proceeds. Approval stays disabled, and any approval attempt is rejected, until the full signed exchange is implemented and proven end to end. | Proven by negative tests showing approval is refused while unimplemented, and later by a full chain test from request through signed approval to execution. |
| `GRAPHOS-A2A-R006` | **Operation invoke and plan-confirm methods for A2A.** graph-os implements graphos.op/invoke and graphos.plan/confirm as A2A methods registered in its method table, so invoking an operation and confirming its input-required approval use the same scope, policy, and error semantics as other hosted operations. | Proven by contract tests asserting invoke and confirm share identical authorization and error codes with the MCP and REST paths for the same operation. |
| `GRAPHOS-A2A-R007` | **Pre-effect audit reservation for every governed write.** Before any governed write or administrative effect, graph-os reserves a tenant-scoped, idempotent audit entry in a pending state, binds it to the verified calling service's claims, and links the entry to the effect's outcome once known. A request with no audit class or an unavailable durable audit writer is rejected before the effect runs. | Proven by negative tests asserting a missing audit class or unavailable writer blocks the effect, and a reconciliation test linking a pending reservation to its final outcome. |
| `GRAPHOS-A2A-R008` | **First-party A2A facade, not a vendored wrapper.** graph-os implements the A2A protocol facade itself as first-party code over the public graph-engine and agent orchestration ports, rather than wrapping or depending on an external vendored A2A implementation. | Proven by a source-level dependency check confirming the A2A facade is implemented in this repository against the public ports. |
