# GRAPHOS-FLEET-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-FLEET-R001` | **Typed pack publisher replaces placeholder ContentPack.** graph-os publishes fleet content packs using the engine-generated SQL record types instead of the placeholder `ContentPack` structure, so SQL and market-data connector items carry real typed schemas when they are added to the catalog. | Integration test asserts published packs use the generated types and that no code path constructs the placeholder `ContentPack`. |
| `GRAPHOS-FLEET-R002` | **Tool schema fingerprints recomputed from served schemas.** Every fleet tool pin's schema fingerprint is computed from the tool's actual served schema rather than an empty placeholder, so catalog entries reflect real input and output shapes fleet-wide. | An automated check re-certifies each pin against its live served schema and fails on any empty-schema fingerprint. |
| `GRAPHOS-FLEET-R003` | **D18 write-back exposed only as a typed, previewed operation.** graph-os exposes the D18 write-back capability solely as a typed, idempotent, previewed registry operation rather than an unguarded native child tool, and the writable connector fleet continues to function correctly across a service restart. | A restart/fault test confirms write-back idempotency and typed preview gating survive a service restart. |
| `GRAPHOS-FLEET-R004` | **Pack annotations carry capability, digest, modality, cost, latency.** Every fleet pack item's catalog entry carries its capability, schema digest, modality, cost and latency annotations, populated across the whole fleet rather than a subset. | A catalog audit test confirms all required annotation fields are present and non-empty for every pack item fleet-wide. |
| `GRAPHOS-FLEET-R005` | **A2A task routing with typed work-item and lease operations.** graph-os routes inbound A2A tasks through typed `GetWorkItem` and `ListWorkItems` operations, exposes capability-based agent search, and issues single-use, provenance-tracked control leases for assigned work. The multiplexer exposes only the subset of tools reachable through this task-routing assembly. | Native library tests cover work-item retrieval, listing, capability search, and control-lease issuance and consumption. |
| `GRAPHOS-FLEET-R006` | **Multiplexer skill and prompt harvest path removed.** The multiplexer no longer harvests or statically hydrates skills and prompts at startup; that code path and its boot-time ingestion are removed once the resident-tool catalog serves the same capability. | A package/runtime audit confirms no skill or prompt harvest or hydration code remains in the shipped package. |
| `GRAPHOS-FLEET-R007` | **Bridge upgraded to FastMCP 4.** graph-os's MCP bridge declares and runs on FastMCP 4, using its native tool, prompt, resource, template and Skills-over-MCP capabilities within a single composed server loop. | A local protocol test suite exercises FastMCP 4 native tools, prompts, resources, templates and Skills-over-MCP against the served bridge. |
| `GRAPHOS-FLEET-R008` | **RUM, security-audit and CI/CD feeds join the catalog.** graph-os adds real-user-monitoring, security-audit and CI/CD event connectors as catalog items, exposing only approved, sanitized data through the same operation registry and tenant boundary as its other feeds. | Integration test confirms each new feed's data passes sanitization and tenant-boundary checks before it appears in the registry. |
| `GRAPHOS-FLEET-R009` | **Run admission evaluates, commits and publishes with capacity control.** graph-os's run admission in `graph_os/a2a/routing.py`, `graph_os/a2a/composition.py` and `control_plane/runs/admission.py` evaluates a candidate run, commits it with synthesis evidence, and publishes it only after an all-or-nothing capacity acquisition. A denied acquisition allows exactly one re-decision, and a stopped run releases its held capacity. | Integration test drives admission through grant, a single re-decision on denial, and capacity release on stop. |
| `GRAPHOS-FLEET-R010` | **Assembly result parsing reads the full agents list.** `graph_os/assembly.py`'s solved-path parser reads the `agents` list field of the generated `AssemblyResult` model and includes every returned `AgentLibraryEntryDraft`, instead of looking for a nonexistent top-level `agent` key or relying on fake dict fixtures. | Unit test uses a real generated `AssemblyResult` instance and asserts all agents are preserved after parsing. |
| `GRAPHOS-FLEET-R011` | **Registry core computes a canonical digest and authorized find.** `graph_os/api/registry/` defines `OpSpec`, its enums, and the `Registry` type with a canonical serialization and a `registry_digest` that identifies the active generation, and `find` evaluates caller authorization at lookup time rather than deferring it. | `tests/api/test_registry.py` covers canonical-form stability, digest computation, and authorized-versus-denied `find` results. |
| `GRAPHOS-FLEET-R012` | **EG-direct binding generator with reviewed exclusions.** `graph_os/api/registry/eg_binding.py` generates registry operation bindings directly from the engine's wire-callable methods, and `eg_exclusions.yaml` records any method intentionally left out along with its reason, so every method is covered by a generated operation or a reviewed exclusion. | `tests/api/test_eg_binding.py` asserts full method coverage by generated bindings plus documented exclusions. |
| `GRAPHOS-FLEET-R013` | **MCP projection exposes the six verbs with typed schemas.** `graph_os/api/mcp/verbs.py`, `discovery.py` and `resources.py` project the registry as the six intent verbs produced by `make_verb`, each with a typed input schema, a `find` operation returning typed schemas, `graphos://` resources, and the active registry digest embedded in server instructions. | `tests/api/test_mcp_verbs.py` validates verb schemas, `find` output, resource URIs, and the embedded digest. |
| `GRAPHOS-FLEET-R014` | **Resolver ranks catalog items with partitioned feedback.** `graph_os/api/mcp/resolve.py` ranks catalog items using lexical and semantic matching over generated descriptors, an exponential moving average of tenant- and policy-partitioned outcome feedback, and a bounded result cache. Natural-language queries produce a preview rather than an executed mutation, and `ask` falls back to a natural-language `query.uql` call when no direct match is found. | `tests/api/test_resolve.py` covers ranking, partitioned feedback, cache bounds, and the NL-to-preview and `ask` fallback paths. |
| `GRAPHOS-FLEET-R015` | **Typed operations cover agents, browser and fleet calls.** `graph_os/api/ops/agents.py`, `browser.py` and `fleet.py` implement typed operations for agent/A2A tasks, reasoning calls, browser actions and fleet calls, where `fleet.call`'s effect classification is derived from the target item's own annotations. `graph_os/fleet/gateway_ops.py` wraps resolution and mounting of catalog tools for these operations to call through. | Integration tests exercise each operation family and confirm `fleet.call` effect classification matches the invoked item's annotation. |
| `GRAPHOS-FLEET-R016` | **Automated gates catch API surface and compatibility drift.** `scripts/check_api_surface.py` and `scripts/check_api_compat.py` run as pre-commit hooks that detect drift in the registry's public API surface and backward compatibility, covering the full gate set defined for this specification. | `tests/api/test_gates_*.py` exercises each gate against both a compliant and a drifted fixture registry. |
| `GRAPHOS-FLEET-R017` | **Authority-parity oracle validates principal, operation and surface.** `tests/api/authority_matrix.yaml` defines the expected authorization outcome for each principal, operation and serving-surface combination, and `tests/api/test_authority_parity.py` asserts the registry's actual authorization decisions match that matrix exactly. | `tests/api/test_authority_parity.py` runs the full principal-by-operation-by-surface matrix and fails on any mismatch. |
| `GRAPHOS-FLEET-R018` | **Multiplexer exposes four resident fleet tools over one catalog.** `api/ops/fleet.py` and `graph_os/fleet/{gateway_ops,catalog_items,session_loads}.py` implement `find_tools` (with `browse=true` replacing a separate catalog listing), `load_tools`, `unload_tools` and `multiplexer_status` over a single catalog filtered per caller, covering fleet tools, prompts, resources, resource templates, agent skills and connector items. Each caller's loaded-tool set defaults to a 64-item cap (hard cap 256) with optional least-recently-used eviction and a one-hour idle expiry, and each loaded tool's body invokes `fleet.call` using the caller's own delegated credential. | Scoped integration tests confirm cap enforcement, LRU eviction, idle expiry, and that invocation always carries the caller's delegated credential. |
| `GRAPHOS-FLEET-R019` | **Eunomia narrows authority at discover, load and call.** `graph_os/api/policy/` applies Eunomia as a narrowing-only policy step in the discover, load and call path, after scope and principal-rule checks and before the deputy and confirmation steps reach the engine; scope filtering always applies even when Eunomia is disabled, and an enabled-but-unreachable Eunomia fails the request closed rather than open. A deployment with no policy configured runs Eunomia off by default, a local deployment ships a default policy with it on, and an external deployment runs it on; `deployment/doctor.py` warns when it is off. | Policy integration tests cover all three default modes plus the fail-closed-on-unreachable and never-unfiltered-when-off cases. |
| `GRAPHOS-FLEET-R020` | **Multiplexer meta-tools register as the four resident tools.** `graph_os/fleet/multiplexer.py` registers its meta-tools as the four resident fleet tools (`find_tools`, `load_tools`, `unload_tools`, `multiplexer_status`), and the per-caller visibility-filtering middleware acts only as a list/call router rather than making authority decisions itself. | Integration test confirms the middleware forwards authority decisions to the registry/policy path and never grants or denies access on its own. |
| `GRAPHOS-FLEET-R021` | **Fleet capability checks require exact scopes, deny unknown tools.** `_require_fleet_capability` requires the exact fleet scope for the requested action and does not accept a broader `admin` or `kg:admin` grant in its place, and it enforces the same check for local stdio connections as for any other transport. `tool_dispatchable` denies any unrecognized native host tool by default instead of allowing it, and the served MCP surface always runs an Eunomia policy filter rather than serving unfiltered. | Tests cover both the previously over-broad path (now denied) and the correctly scoped path (now allowed), plus a served-surface check that Eunomia middleware is active. |
| `GRAPHOS-FLEET-R022` | **Catalog reconciliation re-ingests via durable replay.** graph-os reconciles its served MCP catalog against the engine's durable event log, re-ingesting changed tools, prompts, resources and skills by replaying ordered delta receipts keyed by tenant, generation, sequence and item ID so replays are idempotent. | Integration test replays a delta sequence twice and confirms the resulting catalog state is identical. |
| `PA-12` | **Catalog reload rejects invalid candidates, proves replica convergence.** Fleet catalog reload rejects duplicate, malformed, stale, missing, deleted or digest-mismatched candidate assets without publishing a partial generation, and multi-replica convergence is observed by generation and digest so a replica unable to reach the active generation reports degraded rather than serving a mixed catalog. | Negative-case tests cover each invalid-candidate condition, and a multi-replica integration test confirms convergence reporting. |
| `GRAPHOS-FLEET-R023` | **Connector count pins stay consistent across the fleet.** Every fleet connector count reference — the compatibility matrix, the bundle-catalog schema, the check scripts, `ontology.lock`, the federated IRI, and `genesis.yaml` — reflects the same current total connector count, with no site lagging behind an actual fleet change. | A check script scans all count-pin sites and fails if any of them disagrees with the live connector count. |
| `GRAPHOS-FLEET-R024` | **Fleet reconciliation, scaling and deploy watch are served by GraphOS.** GraphOS owns the fleet reconciler, autoscaler, scaling authority and deploy-watch behavior that previously sat beside the agent runner in the agent runtime's `orchestration/` package. They run as GraphOS services behind typed operations with the same caller verification, policy filter and audit as other fleet operations, and the agent runtime keeps only the agent runner and planning code and reaches fleet behavior through those operations. | Parity tests reproduce the prior reconcile, scale-up, scale-down and deploy-watch decisions through the GraphOS operations, negative tests refuse an unauthorized caller, and a census shows the agent runtime no longer ships these modules. |
