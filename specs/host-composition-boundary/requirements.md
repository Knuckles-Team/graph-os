# GRAPHOS-HOST-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `GRAPHOS-HOST-R001` | **Cross-repository composition boundary assignment.** GraphOS composes its runtime gateway on top of boundary contracts in which the graph engine owns ontology, SHACL and durable graph records, the connector SDK owns connector transport, and the agent runtime exposes only its public agent control-plane API; the web UI consumes this composed boundary rather than any internal package. | An import-boundary census confirms each dependency is reached only through its published public API, enforced as a continuous-integration check. |
| `GRAPHOS-HOST-R002` | **Graph engine client exposes the session/discovery surface.** The graph engine's client library exposes session, engine, source-sync, shard-topology, fleet-catalog and discovery-authority methods that GraphOS's gateway and fleet modules call directly, so migrating that code out of the agent runtime does not require reimplementing this surface. | A contract test against the installed graph engine client confirms each required method is present and callable before the dependent modules are migrated. |
| `GRAPHOS-HOST-R003` | **Web UI rename cutover across GraphOS.** GraphOS's import sites, optional web UI package extra, package source reference, release workflow checkout step, preflight checks, and browser-control tests and docs all reference the renamed web UI package. | A focused test run and the offline lock check confirm every reference resolves against the renamed package. |
| `GRAPHOS-HOST-R004` | **Single gateway implementation under graph_os/gateway.** GraphOS retains one gateway implementation under `graph_os/gateway/`, incorporating any behavior unique to the agent runtime's duplicate gateway package once that duplicate is removed, reconciling the `schemas/graph_core` and `ontology_api` modules against their counterparts, and dropping the `graph-os-daemon` console script and the `gateway-widgets` package extra. | A package-layout test confirms no duplicate gateway implementation remains and the retired script and extra are absent. |
| `GRAPHOS-HOST-R005` | **graph_os.mcp_server.runtime serves retired MCP actions.** GraphOS's `graph_os/mcp_server/runtime.py` serves every MCP action the agent runtime's legacy MCP host previously provided, verified against an approved action-to-operation mapping, once that legacy host is retired. | A parity test maps each served MCP operation to the approved registry and confirms no action is dropped without a recorded mapping. |
| `GRAPHOS-HOST-R006` | **graph_os.fleet is the sole multiplexer and host owner.** GraphOS's `graph_os/fleet/` package is the sole multiplexer implementation and additionally hosts the OAuth broker, task-extension, principal, harness-server, middleware, skill-coverage and environment-drift-check modules that only GraphOS imports. | A package-layout test confirms the duplicate multiplexer no longer exists outside `graph_os/fleet/` and each moved module resolves only through GraphOS imports. |
| `GRAPHOS-HOST-R007` | **Agent runtime imported only through its public API.** GraphOS imports the agent runtime exclusively through `agent_utilities.api`, with every other import site rewired to a GraphOS-owned module or the connector SDK's public interface, and `graph_os/tests/test_package_layout.py` enforces this as an `agent_utilities.api`-only fence. | The package-layout test fails on any import of an agent-runtime module outside `agent_utilities.api` and passes once the rewiring is complete. |
| `GRAPHOS-HOST-R008` | **GraphOS hosts its own boundary modules.** GraphOS hosts its own security request-identity, error-surface, browser-auth and security-policy-middleware modules with their conformance tests; its own gateway and runtime health and metrics observability; its own profile-guard, install, release-channel, live-mount-guard, paths, workspace and config-admin core modules; its own hook-installer, agent-manager-dashboard, release-catalog and gateway-client modules; and its own connection-registry and engine-discovery modules under `graph_os.fleet`. | A package-layout census confirms these modules are imported only from their GraphOS location and the agent runtime no longer declares equivalents. |
| `GRAPHOS-HOST-R009` | **GraphOS hosts the agent HTTP server and A2A endpoints.** GraphOS hosts the agent HTTP server under `graph_os/a2a/` and `graph_os/webui_host/`, including the A2A, A2A-config and A2A-graph-skill protocol modules migrated from the agent runtime; the duplicate broker and its separate task store are not ported, since durable task state has a single owner. The editor-facing Agent Client Protocol is provided by the agent runtime's harness integration, so GraphOS carries no ACP adapter of its own and mounts that implementation where a deployment exposes it. | Route and task-lifecycle tests cover the hosted A2A endpoints, and a source check confirms GraphOS contains no separate ACP adapter implementation. |
| `GRAPHOS-HOST-R010` | **GraphOS owns hosting/deployment configuration settings.** GraphOS owns the hosting and deployment configuration settings split out of the agent runtime's monolithic configuration module, while connector base settings move to the connector SDK's own configuration module and agent/model settings remain with the agent runtime. | A configuration-schema test confirms GraphOS resolves its hosting and deployment settings from its own module without importing the agent runtime's configuration internals. |
| `GRAPHOS-HOST-R011` | **GraphOS serves the messaging channel and routing layer.** GraphOS serves the messaging channel adapters, listener, service, daemon, polling, reaper and host routing for the agent bus, while the graph engine remains the sole authority for durable message append, reads, cursors, dead letters and depth. | A served test exercises a messaging action through GraphOS and confirms the graph engine records the durable result exactly once. |
| `GRAPHOS-HOST-R012` | **Component registry carries GraphOS and SDK boundary entries.** GraphOS publishes boundary seed entries for itself and the connector SDK in the architecture component registry, each naming its owning modules and public import surface. | A registry-completeness check confirms GraphOS and the connector SDK each have a registry entry with no coverage gap. |
| `GRAPHOS-HOST-R013` | **Front ends import only public GraphOS/agent-runtime surfaces.** GraphOS's web UI package imports the agent runtime only through `agent_utilities.api`, directly from GraphOS, or from the graph engine's client library, with no import of an agent-runtime-internal module. | A package-layout test on the web UI package fails on any import outside these allowed surfaces. |
| `GRAPHOS-HOST-R014` | **Agent runtime split into connector SDK, GraphOS and engine.** The former agent runtime is split into separately published repositories: the connector SDK, GraphOS, and the graph engine, each publishing its own installable package so GraphOS depends on the others only through their public APIs. | GraphOS's dependency manifest pins each split repository's published package rather than a path into the former combined source tree. |
| `GRAPHOS-HOST-R015` | **Layered agent capability model with a harness abstraction.** GraphOS defines a layered agent-capability model, from its lowest to its highest defined layer, implemented over the graph engine, together with a harness abstraction that lets a given layer run under different execution environments. | A conformance test suite exercises each defined layer through the harness abstraction and confirms its expected behavior boundary. |
| `GRAPHOS-HOST-R016` | **main branch includes the published dependency composition.** GraphOS's default branch history includes the published composition of the graph engine, connector SDK and agent runtime dependencies, so later changes build on that composition rather than reverting behind it. | A git ancestry check in continuous integration confirms the published composition commit remains reachable from the default branch. |
